## Highlights

### AI

- AI-first general-purpose assistant with Gemini-powered multimodal replies
- Four reply modes: Chat, See (image understanding with attachments), Draw (image generation), Speak (text-to-speech)
- Threaded conversations with sidebar navigation
- Credit-based system: 1 AI Credit per chat message, exchanged at 10 NOVA Coins → 1 Credit
- Server-authoritative credit reservation/refund via two-phase commit (`reserve_chat_credit` → Gemini → `finalize_chat_credit`)
- Conversation history persists server-side; stale reservations auto-cleaned (>5 min)

### Games

- **Tic-Tac-Toe** — 10 NOVA Coins + 25 XP for win; server-validated completion
- **Sudoku** — 20 NOVA Coins + 40 XP for completion; 3 puzzles with known solutions
- **Ball Run** — 15 NOVA Coins + 30 XP, survive 60 seconds; server-derived score
- **Water Sort** — 15 NOVA Coins + 35 XP, sort every tube; move-count-derived score
- All four games lazy-loaded via code splitting; Ball Run largest chunk at 59.88 kB gzip
- Game completions validated inside `SECURITY DEFINER` RPCs; Edge Functions add additional validation

### Progression

- **XP** — Per-game completion; contributes to level
- **Levels** — XP-based progression
- **Achievements** — Catalog of 5 catalog rows seeded via migrations
- **Streaks** — Server-authoritative via `touch_user_streak()` RPC with CHECK constraints
- **Leaderboard** — `leaderboard_ranked` view: public projection (rank, display_name, XP, level, is_me)

### Economy

- **NOVA Coins** — Earned in games; 10:1 exchange rate to AI Credits
- **AI Credits** — Consumed 1 per chat message; replenished via coin exchange
- **Wallet** — Server-side balance; session-local 20 coins / 0 credits in demo mode
- **Transaction ledger** — Read-only; every row shows balance impact and timestamp

### Security

- All wallet mutations go through `SECURITY DEFINER` RPCs with `search_path = public`
- RLS policies on all tables restrict SELECT/INSERT/UPDATE to `auth.uid()`-owned rows
- Gemini API key stored as Supabase secret, never exposed to the browser
- No browser client can directly modify `wallet`, `wallet_transactions`, `game_results`, or `game_progress`
- Idempotency keys (`game_completions`, `exchange_requests`, `chat_requests`) prevent duplicate rewards
- Two-phase chat credit commit: `reserve_chat_credit` → Gemini call → `finalize_chat_credit`
- Stale reservations (>5 min) auto-cleaned on next `reserve_chat_credit` call
- Storage bucket `chat-attachments` is private; owner-scoped policies (INSERT/SELECT/DELETE require `(storage.foldername(name))[1] = auth.uid()::text`)
- Edge Function path validation prevents path traversal, absolute paths, empty segments, prefix tricks
- `SUPABASE_SERVICE_ROLE_KEY` only in `delete-account` function (server-side, read from `Deno.env.get()` after JWT verification)

### Performance

- Initial JS: 133.29 kB gzip
- Total JS: ~210 kB gzip across 5 chunks
- Largest game chunk: Ball Run at 59.88 kB gzip
- 320/320 tests passing (Phase 21 verified)
- TypeScript: 0 errors, ESLint: 0 errors (Phase 22 verified)
- Production build: PASS

### Known limitations

- **PWA formally deferred** per security review — no service worker or manifest implementation
- **Screen-reader testing** unavailable during audit — accessibility validation required post-launch
- **Direct RPC call risk** — `complete_tictactoe_game`, `complete_sudoku_game`, `complete_water_sort_game`, `complete_ball_run_game` trust their parameters; validation lives in Edge Functions, not database (bounded damage: one session, one payout, fixed constants)
- **No application-layer rate limiting** — only Supabase Auth email/password limits; credit cost (1 per chat message) is the only economic brake
- **`leaderboard_ranked` publishes display names** — grants SELECT to `anon`; not `security_invoker`, so display name, XP and level of any profile with `xp > 0` are world-readable (deliberate product choice)
- **`audit_log` has no writer** — table exists with SELECT-own RLS, but no function inserts rows into it
- **Account deletion does not remove Storage objects** — images already uploaded to `chat-attachments` are orphaned rather than deleted (FKs do not cover Storage)
- **Legacy whole-account history path** — `get_chat_history` with `NULL` conversation id still returns the account's last N messages; kept for backward compatibility
- **No automated secret scanning or CI gate** — enforcement is the test suite in `supabase/tests/` plus `npm run lint` / `npm run build`, run manually

## Deployment

Release candidate. See Phase 23 Step 6 for exact deployment actions required:

1. Create Supabase project, apply 31 migrations in order
2. Set Edge Function secrets: `GEMINI_API_KEY`, `CORS_ALLOWED_ORIGINS`
3. Deploy 7 Edge Functions: process-tictactoe, process-sudoku, process-ball-run, process-water-sort, nova-chat, exchange-nova-coins, delete-account
4. Set production `.env` on host: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`
5. Deploy `dist/` to static host (Vercel, Netlify, etc.)
6. Configure Supabase Dashboard: Site URL, Redirect URLs, Email providers
7. Deploy Edge Functions and verify
